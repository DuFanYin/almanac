# Almanac

[English](README.md)

一个个人投资系统，把通常混在一起的三件事分开：可能发生什么、你偏好什么、该做什么。

- **可能发生什么**是一套概率，叫"世界"：给 1971 年以来历史上的每一周一个权重，表示那一周之后的日子和接下来的日子有多像。先由今天的指标移动它，再由 LLM 写的情景（每个情景给一个概率）再移动一次。
- **你偏好什么**（风险档位、目标比例、坏情形的上限）从不改变任何概率。
- **该做什么**由一个机械的决策步骤给出：把前两者合起来，守住你的上限，再换算成对现有持仓的交易。

每个预测、每个情景都由数据结算、打分。每个数字旁边都保留不用 LLM 时的同一个数字。它只给建议，从不下单。

## 用到的词

| 词 | 意思 |
|---|---|
| 指标（Indicator） | 每天从数据算出的读数（VIX、信用利差、美联储的动作、估值、LLM 读出的文本），分绿、黄、红，并写明它预期对各因子说明什么。代码里叫 signpost |
| 因子（Factor） | 描述"发生了什么"的七个量：标普 500 的回报、10 年期收益率和实际收益率的变化、通胀的年率、失业率的变化、美元的回报、金融条件（NFCI） |
| 时间长度（Length） | 往后看多远：一周、一个月、三个月、一年、三年 |
| 各种未来（The futures） | 1971 年以来该长度的每一段历史时期，各是一种可能的未来，各有权重 |
| 模拟（The simulation） | 只按今天的指标加权的各种未来 |
| 情景（Scenario） | LLM 为一个时间长度写的一个故事：一两个因子的范围。一段历史可以落在几个情景里，也可以一个都不落 |
| 世界（The world） | 放进情景概率之后的模拟：所有预测和决策读的唯一信念 |
| 平常（Usual） | 不加权的历史时期本身 |
| 坏情形（Bad case） | 你的目标组合在最差 10% 未来里的平均结果 |

## 怎么工作

| 部分 | 做什么 | 为什么单独分开 |
|---|---|---|
| 指标 | 三十个左右，每个写明它对因子应有的说明（哪个方向、哪段时间、为什么）。每个都在历史上从一周到三年分段测量，只按预期的方向使用，并按它自己的噪声收缩；它的消息管多久是测出来的，不是设定的 | 证据有自己的时间尺度：极度恐慌说明的是接下来几周，美联储收紧说明的是接下来几年 |
| 模拟 | 每个指标按今天在它自己历史中的位置，推动它覆盖的那些长度上的因子；历史各周的权重按所需的最小幅度调整，从不压到少于四分之一的历史周 | 一套权重、在任何长度上读，就是唯一的信念 |
| 情景 | 每周在一个月、三个月、一年、三年四个长度上，由一个 LLM 写出现在值得区分的情景。四个 LLM 读者（宏观经济学家、市场史学者、乐观者、悲观者）各自读一个情景，说它比模拟给的可能性高或低多少倍，依据是模拟没有包含的东西。一个审阅者对照数据检查他们的理由。每个情景的概率 = 模拟的概率 × 读者倍数的中位数；历史各周的权重调整到满足这一点为止 | 历史上互不重叠的三年期很少，也没有还没发生过的事；LLM 是刻意引入来补这一块的 |
| 资产类别 | 每个类别怎么跟随因子：按长度在 1971 年以来的每个窗口上拟合（总回报），拟合解释不了的部分按窗口保留，所以一起跌过的类别会一起跌；现金和国债用今天的收益率 | 同一个结果，在 5% 收益率下和 1% 收益率下的回报不一样 |
| 偏好 | 五个风险档位（坏情形上限、现金下限、单类上限、一个类别最多可调多少、再平衡带、步长），你的目标比例和上限，比特币的上限和定投 | 同样的信念，让谨慎的人和大胆的人得到不同的组合，但概率从不因人而异 |
| 决策步骤 | 在每个长度上，取每个类别在今天世界中的预期回报减去平常的，再减去纯属偶然会有的差距，分成数据和 LLM 两部分，各乘它的灵敏度；据此调整你的目标比例，每类不超过上限；然后过护栏（每个长度的坏情形在上限之内）；最后换算成对现有持仓的交易：超出再平衡带或移动了半步才交易，一次一步 | 从世界到交易只有一条路：同一条消息只起一次作用，好消息和坏消息一样起作用，而且这个步骤可以在历史上回放 |
| 预测 | 由数据结算的问题（标普 500 两年走势、2027 年衰退、美联储决议、CPI 公布值、基金区间），每个都从世界中读出，有 Kalshi 价格的再和价格合并 | 它们给世界打分、展示世界，但不驱动任何决定 |

## LLM 怎么用

LLM 是刻意引入的，用来提供历史和数据给不了的东西。偏好由你定；结算和计算都是机械的。

- **几个 LLM，各管一件事。** 写情景的、四个读者、审阅者（不给任何数字）、以及读每个角色得分的教练。情景每周修订一次，某个因子异常变动时再修订。一个情景对你的目标是好是坏是算出来的，从不问 LLM。
- **它给的倍数原样使用。** 不向 1 收缩。每组情景到期后打分，分数在下一次告诉 LLM。
- **它两个方向都起作用。** 它那部分的差距按你给它的灵敏度（默认 1.0）调整目标比例；护栏仍然优先。
- **有不用它的对照。** 每个数字也在不含任何 LLM 产出的情况下算一遍，并列显示。
- **它把文本读成数字。** 美联储声明（多鹰派）、新闻和最大几家 AI 投资方财报里关于 AI 投入的部分、当天的标题（什么情绪）：每段文本读三遍，打到一个刻度上，引用的原话必须逐字出现在文本里才算数。只读 2026 年 10 月 30 日以后的文本，因为模型知道更早的文本后来怎样了。
- **它提议。** 每周最多三个预测、每四周最多两个因子，都先用数据检查。你放着三天不管的，由 LLM 决定（问三次，多数通过；每月最多两个预测、一个因子）；任何已采纳的你都可以撤回。
- **它写东西。** 每周简报和反对你持仓的理由，其中每个数字都必须是给它的数据；每四周为本周关键预测写研究笔记，数字与来源不符的论点会被删掉。
- **它从不**设定阈值、步长、上限或灵敏度；不下单，不定交易大小；不结算结果；不给自己打分；不修改已登记的问题。

## 结果出来之前就做的检查

| 检查 | 抓住什么 |
|---|---|
| 每个类别对因子的拟合，在留出的历史段上做样本外检验 | 只会描述过去的拟合 |
| 每个指标对照它的预期，按长度检验，控制错误发现率 | 碰巧看起来有预测力，或和它的机制反着说的信号（不用） |
| 决策步骤从 1981 年起每四周回放一次，用当时能建出的世界；灵敏度在前半段选、在后半段评，对照再平衡的目标组合、风险档位的组合和 60/40 | 比直接持有组合没有增益的决策 |
| 每个类别在每个长度上和平常的差距，旁边列出纯属偶然会有多大 | 换一组历史样本就会反过来的调整 |
| 每条规则的阈值在历史上往两边移动 | 阈值的确切位置全靠运气 |
| 规则、情景写法、提议的每个版本都计数 | 靠多次尝试换来的好记录 |

## 现状和局限

- **还没有实盘得分。** 第一批预测从 2026 年 11 月下旬开始结算；第一批一个月的情景在写出一个月后结算。
- **回放发现按数据调整没有增益。** 从 1981 年起，没有哪个灵敏度在前半段每年多赚 0.2 个点而不加深回撤，所以数据那部分设为 0，只由护栏和再平衡带起作用。每月第一个周六重新回放。LLM 的情景和市场价格无法为过去重建，所以 LLM 那部分没有经过检验。
- **护栏有成本。** 在历史上，坏情形上限每年大约少赚 0.7 个点，也没有让 2000–02 年的下跌更浅；它们是偏好，照设定保留。
- **长时间段的历史很薄。** 1971 年以来互不重叠的一年期约 54 段，三年期 17 段。
- **因子解释不了的。** 黄金和比特币大部分无法用这些因子解释；比特币用它自己的历史，没有世界能据以读它的指标。
- **只用一个模型家族**（DeepSeek）；多样性来自不同视角、措辞和刻意略去的数据。
- **不构成投资建议。**

## 快速开始

```bash
uv sync --all-groups                       # Python 和依赖（pyproject.toml、uv.lock）
cp .env.example .env && chmod 600 .env     # 模型服务商和密钥
uv run python -m src.board.run --no-llm    # 跑一天的看板，不调用 LLM
uv run python -m src.board.run             # 完整的一天，包括 LLM
uv run python -m src.web                   # 页面：http://127.0.0.1:8083
uv run pytest                              # 测试；不调用模型，不联网
```

其他命令（按需生成每周简报、研究、情景或提议，历史回放，查一个数字的来源）用 `python -m src.board.run --help` 查看。

要每天自动运行：在美股收盘后、刷新持仓文件的程序之后，定时运行 `python -m src.board.run`（systemd timer 或 cron），并让 `python -m src.web` 常驻。页面本身没有登录：在本机打开，或者放在一个会要求登录的服务器后面。

## 你自己的设置

关于你的一切都放在 `local/`，git 不跟踪它。没有它，看板按默认设置运行。

| 文件 | 内容 |
|---|---|
| `local/rules.toml` | 你的风险档位（1 到 5）、你的类别和目标比例、每个代码属于哪个类别、比特币的上限和定投、你的规则。从 `src/board/config/rules.example.toml` 复制开始 |
| `local/settings.toml` | `positions`：一个记录你持仓的 JSON 文件，由别的程序和券商保持同步（格式见 `src/board/data/account.py`；没有它就没有账户部分）；`notify`：一个以一条消息为参数的命令；`research_model`；`[web]`：页面页头的链接，默认没有 |
| `local/questions.toml`、`local/factors.toml` | 从 LLM 提议中采纳的预测和因子，由看板写入 |

同样不进 git 的：`.env`（模型服务商和密钥）和 `data/`（看板的产出，以及你在页面上的输入）。

## 目录

三层，单向依赖：模型层、研究、看板；页面在最上面。每层只引用它下面的层（`tests/test_layers.py`）。

| 路径 | 内容 |
|---|---|
| `src/llm/` | 模型层：服务商设置、带模型链的客户端、调用记录和费用，以及让回答可检查的方法：`propose`、`forecast`、`scenarios`、`write`（写出的每个数字都必须是它引用的数据项）、`indicators`、`readings`（把一段文本读到刻度上）；其中 `forecast`、`write`、`indicators` 也能当命令行用，JSON 进 JSON 出（`python -m src.llm.methods`） |
| `src/research/` | 研究，一个库：为一个问题搜新闻，读成经过检查的笔记，再在笔记上跑预测方法 |
| `src/board/` | 看板：`core/`（数据库、来源追溯、指标的表达式语言）、`data/`（数据源、检查、账户文件、LLM 的文本）、`model/`（纯计算）、`steps/`（一天里每一步一个模块）、`pipeline.py`（它们的顺序）、`calibrate.py`（每个指标的消息管多久，以及历史回放）、`view/`（页面的数据）、`config/`（数据序列、指标、因子、资产类别、预测） |
| `src/web/` | 页面：`app.py`（路由、接口、静态资源）、`static/`（页面、脚本、样式）、`design/`（共用样式、图表辅助、字体、图标） |
| `tests/` | 每层一个文件夹，加上 `test_layers.py` |
